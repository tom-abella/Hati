# Hati budget — early preview

This is an incomplete prototype. Guests can browse; signing in is required to view or save account-specific local records. It is **not ready for financial records**: transaction sync and scheduled push require the migrations below and have not been tested against the hosted project; bills, budgets and cutoff planning are incomplete. Anyone with access to this browser profile can read local data, and browser storage can be cleared. Do not enter card numbers or sensitive information.

## Run

Requires Node.js 20.9 or later. Run `npm install`, `npm run build`, and `npm start`. Open `http://localhost:3000`. The service worker is disabled in development; offline behavior requires a production build and HTTPS (localhost is also supported). An initial online load is required. Installability on iOS and offline reopening have not been verified on a physical device. The SVG icon still needs iOS-compatible PNG icons.

Income and expenses are stored per account in IndexedDB in integer centavos, with an atomic sync queue. Cards, reminders, and confirmed document details use the same queue. Existing account records are queued once on upgrade. After the database migrations are applied, sync runs on app open, focus, reconnect, and local changes; pending count and last sync appear in the app. Supabase records use ownership policies, unique IDs and transaction deletion tombstones. Existing records from the separate `hati-local-preview` database are not imported. The monthly view and CSV use local data. Available credit starts at the limit, subtracts recorded expenses and adds legacy paid reminder amounts or reviewed statement allocations; undoing a payment reverses it. Record existing balances as expenses for an accurate result. Reminder updates detect concurrent edits and retain local changes on conflict rather than silently overwriting them. Notification schedules and payment changes made offline reach the server only after sync.

### Supplementary cards and statements

Under Cards, the primary card owner can invite a cardholder by their confirmed account email and set a supplementary limit within the primary limit. The recipient signs in and accepts under Cards; the app does not send invitation emails. Either participant can record supplementary expenses by selecting that card in manual Transactions. Shared activity and the shared available-credit estimate are visible to both participants; their unrelated transactions remain private. Invitations and accepting or revoking access require a connection. Supplementary expenses use the offline sync queue once the card has been loaded, and shared data refreshes on sync or focus. Shared data is cached per account on the device; access revocation takes effect on the server immediately but cached copies remain visible until that device reconnects and syncs.

For a full statement payment, add a card reminder with the statement closing date. When marking it paid, select only the recorded primary and supplementary purchases included in that statement. The app freezes those allocations, leaving later or subsequently recorded purchases outstanding; undoing the payment releases them. A paid allocation must be undone before its transaction can be deleted. Earlier payments without allocations are still treated as unallocated totals, so check older purchases carefully before selecting them for another statement. Credit is an estimate based only on recorded activity, and fees, refunds, unrecorded purchases or bank allocation rules can cause it to differ from the bank.

### Push notifications

Run `npx web-push generate-vapid-keys`, then copy `.env.example` to `.env.local` and fill in the Supabase settings, VAPID public and private keys, a `mailto:` VAPID subject, a long random `CRON_SECRET`, and the Supabase service-role key. Set the same variables in the deployed server environment; only the `NEXT_PUBLIC_` values belong in browser code. Apply `supabase/migrations/20261111000001_push_reminders.sql` after the earlier migrations. Enable `pg_cron` and `pg_net` in Supabase, replace the URL and secret placeholders in `supabase/cron.sql`, and run that file manually. The URL must be a deployed HTTPS URL reachable by Supabase, not localhost. The SQL contains your secret once filled in; do not commit it.

Use a production build for local push testing because the service worker is disabled in development. On iOS 16.4 or later, add Hati to the Home Screen and open it from there before enabling notifications. HTTPS is required except for localhost. Notification delivery depends on the scheduler, push service, and device connectivity, and is not guaranteed. Reminders are claimed before delivery to avoid duplicate sends; a server or push-service failure after claiming will not be retried. Push subscriptions are device-specific and associated with the signed-in account; enable notifications on each device and disable them before switching accounts on a shared device.

Image entry reads JPEG, PNG or WebP images in the browser using Tesseract.js. Single-entry mode suggests a merchant, ISO-format date and total; Apple Pay history mode suggests multiple entries for selection and review. Relative dates use the screenshot capture time entered in Asia/Manila, initially set to upload time; weekday labels use the most recent earlier occurrence, except the capture weekday itself is left blank as ambiguous. Ambiguous numeric dates require a date-order choice. A user can mark a screenshot as taken in the Philippines to suggest PHP for entries without a recognized currency; detected foreign currencies still require review. Possible duplicate dates and amounts are flagged but require a decision. OCR may miss or misread transactions, dates, currencies, pending or refunded items, and needs an initial download of OCR assets; offline availability has not been verified. Newly selected images are held temporarily and are not saved. Previously saved image drafts and images remain on the device and are not synced. Confirmed document details are synced, but bill and statement references do not create bills, payment occurrences or reminders.

### Email confirmation troubleshooting

Supabase's default email service only sends to addresses belonging to the project's organization team and is currently limited to two emails per hour, best effort. For other addresses, configure [custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp) in Supabase Authentication settings. Check the spam folder and Auth logs for delivery or rate-limit errors. In **Authentication → URL Configuration**, set the Site URL to the actual app URL: `http://localhost:3000` works only on the computer running the app, not on an iPhone. After deployment, use the HTTPS app URL.

## Database setup

Apply migrations in `supabase/migrations` in filename order, including `20261111000001_push_reminders.sql` before `20261111000004_payment_reminder_sync.sql`, `20261111000005_edit_delete_cards.sql` for cards, `20261111000006_edit_delete_reminders.sql`, `20261111000007_supplementary_cards.sql` and `20261111000008_supplementary_statements.sql` for sharing, and `20261111000009_remove_supplementary_cards.sql` for supplementary-card removal. Do not rerun migrations already applied. Migration 08 disables the older reminder-write functions to protect statement allocations, so deploy the updated app immediately afterwards and refresh every device. The `supabase/` folder is Git-ignored; apply these SQL files manually. Card removal keeps the card record as a tombstone so linked transactions and reminders retain their history. Removing a supplementary card revokes access and hides it, but its recorded purchases remain part of the primary card balance. Deleting a paid card reminder removes its payment from the available-credit calculation and cancels its scheduled alert when synced. The app uses the signed-in user's publishable-key client and RLS. Sync and RLS have not yet been verified against the hosted project; test with two accounts and two devices before relying on it. Do not use the database dashboard to physically delete transactions, cards or reminders: sync relies on tombstones. The app does not yet provide a conflict-resolution interface. Never expose a secret or service-role key.

## Platform notes

Checked November 2026: [Next.js](https://nextjs.org/docs/app/getting-started/installation) requires Node 20.9+; [Serwist's Next integration](https://serwist.pages.dev/docs/next/getting-started) supports webpack, used by the build script. [Supabase Free](https://supabase.com/pricing) includes 500 MB database storage, 500,000 Edge Function invocations and two active projects, but projects may pause after one week of inactivity. [Vercel Hobby](https://vercel.com/docs/plans/hobby) is free for non-commercial personal use and has usage limits; exceeding limits may interrupt service. Limits can change.

Before this can meet the requested design it needs hosted sync and ownership testing, edit/conflict handling, a safe import of legacy preview entries, syncing of other entities, recurring occurrences and payment allocations, configurable cutoffs, reports, and end-to-end security and physical iPhone tests. Push needs connectivity and notification permission in an iOS Home Screen app, and delivery is not exact. A free project pausing can stop reminders.
